# ACMER Studio on Linux — Bottles + GE-Proton

> **Context**: the latest ACMER Studio is distributed as a `.exe` for Windows
> and runs on Linux via **Bottles** (Flatpak) with the **GE-Proton11-3** runner.
> Here we document the validated step-by-step: installation, filesystem
> permissions, runner, `winecfg` tweaks, and what already works.
>
> **Date**: 2026-08-09 · **Bottles** (Flatpak) · **GE-Proton11-3** · **ACMER Studio**
> (executable: `download/ACMERStudio.exe`)

**Status**: app runs, renders correctly, saves projects, exports G-code, and
edits file names. **Resolved**: keyboard issue in dialog — cause: Wine in
unmanaged mode + native modal dialog; fix: **virtual desktop** (section 4).

---

## Quick Summary (step by step)

1. Install Bottles: `flatpak install flathub com.usebottles.bottles`
2. Create the bottle pointing to a directory in `~/`; run the filesystem
   permission command that Bottles provides (terminal), close, and restart
   pointing to the same directory
3. Bottle runner: choose **GE-Proton11-3** when creating the bottle
   (install it first, if needed: Bottles → Preferences → Runners)
4. Install ACMER Studio in the bottle
5. `winecfg` (bottle console) → **Graphics** tab:
   - uncheck *"Allow the window manager to control the windows"*
   - uncheck *"Allow the window manager to decorate the windows"*
   - check **"Emulate a virtual desktop"** (1920×1080) ← fixes the keyboard
     in save/export dialogs
6. Copy the tool DLLs to the exe directory (section 5) —
   without this, Calibrate/PathOpt/BatchDup won't load
7. Run ACMER Studio via Bottles

Details: sections below.

---

## 1. Install Bottles (Flatpak)

```bash
flatpak install flathub com.usebottles.bottles
```

---

## 2. Create the Bottle Pointing to a Directory in `~/`

1. Open Bottles → **+ New bottle**.
2. Give it a name (e.g.: `acmer-studio`).
3. In **Directory**, point to a folder in `~/` (e.g.:
   `~/acmer-studio-files`) — **outside** the Flatpak sandbox.
4. Bottles detects that the directory is not accessible within the sandbox and
   provides a **command to run in the terminal** that grants this permission.

> The exact command is generated by Bottles — run whatever it shows.
> The pattern is a filesystem override, something like:
>
> ```bash
> flatpak override --user --filesystem=/home/username/acmer-studio-files com.usebottles.bottles
> ```

1. Run the command in a terminal, **close Bottles**, and restart the process,
   pointing to the **same directory**.
2. Now Bottles accepts the directory — create the bottle normally.

---

## 3. Runner: GE-Proton11-3

The bottle must use the **GE-Proton11-3** runner, chosen **at bottle creation**
time (+ New bottle → Runner field).

If the runner is not yet installed: Bottles → **Preferences** →
**Runners** → install **GE-Proton11-3** before creating the bottle.

---

## 4. winecfg Adjustments (windows) — mandatory

Without these steps the app won't start properly. With the bottle selected:

1. **Console** (from the bottle) → run:

   ```bash
   winecfg
   ```

2. **Graphics** tab → **uncheck** both items:
   - `Allow the window manager to control the windows`
   - `Allow the window manager to decorate the windows`
3. Still in **Graphics** → check **"Emulate a virtual desktop"** with
   full resolution (e.g.: 1920×1080).

> **Why the virtual desktop**: with WM control off, Wine manages X11 focus
> alone and native modal dialogs (save/export G-code) don't receive keyboard
> focus — you can't type the file name and the window seems frozen (known Wine
> bug). With the virtual desktop active, Wine controls focus internally and
> the dialog works again. Validated on 2026-08-09.

---

## 5. DLL Verification (mandatory before running)

The tool DLLs shipped with ACMER Studio live in subfolders under
`resources\tools\win\` (`Calibrate\`, `PathOpt\`, `BatchDup\`). Wine's DLL
search order is: exe directory → system32 → PATH — and these folders are not
in the bottle's PATH. Result: `Calibrate`, `PathOpt`, and `BatchDup` tools
fail to load (`err:module:import_dll` in the log).

**Fix**: copy the tool DLLs to the exe directory (first place in search order).
Also copy `libvkd3d-utils-1.dll` from the runner to the bottle's system32
(silences the DXCore fallback noise — rendering already goes through DXVK).

Single block, ready to paste in a Linux terminal:

```bash
APP="/home/username/acmer-studio/acmer-bottle/drive_c/Program Files/ACMER Studio"
BOTTLE="/home/username/acmer-studio/acmer-bottle/drive_c/windows"
RUNNER="$HOME/.var/app/com.usebottles.bottles/data/bottles/runners/ge-proton11-3"

# Tool DLLs (Calibrate/PathOpt/BatchDup) -> exe directory
cp "$APP/resources/tools/win/Calibrate/"*.dll "$APP/"
cp "$APP/resources/tools/win/PathOpt/"*.dll "$APP/"
cp "$APP/resources/tools/win/BatchDup/"*.dll "$APP/"

# libvkd3d-utils-1.dll (missing from bottle, exists in runner) -> system32/syswow64
cp "$RUNNER/files/share/default_pfx/drive_c/windows/system32/libvkd3d-utils-1.dll" "$BOTTLE/system32/"
cp "$RUNNER/files/share/default_pfx/drive_c/windows/syswow64/libvkd3d-utils-1.dll" "$BOTTLE/syswow64/"
```

(34 DLLs + 2 from vkd3d. Revert: `rm` of the copied DLLs — only those that
aren't from Electron; or reinstall the app.)

**Validated on 2026-08-09**: `err:module:import_dll` errors for
opencv/ceres/ortools/tinyxml2/onnxruntime/libsodium no longer appear.
Calibrate/PathOpt/BatchDup tools load.

## 6. Running ACMER Studio

```bash
# Bottle console
wine /path/to/ACMERStudio.exe
```

**Validated — works:**

- Interface renders correctly
- Projects save
- G-code export works
